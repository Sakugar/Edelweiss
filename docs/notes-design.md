# Edelweiss 群聊笔记设计

主 Agent 在处理群聊时可以自主保存值得以后参考的信息，例如群内约定、项目决议和纠正过的旧结论。记笔记可以与发言发生在同一轮，也可以静默完成。笔记按平台和会话保存，服务重启及对话压缩后仍可读取。

## 两种加载方式

| 类型 | 使用方式 | 适合内容 |
| --- | --- | --- |
| `always` | 每轮加载完整正文 | 持续影响聊天的称呼、用语和群约定 |
| `on-demand` | 每轮展示相关条目的简短索引，由 Agent 按需读取正文 | 项目细节、具体流程、历史决议和复盘 |

两种笔记共用同一个 Markdown 格式。以文件名作为稳定 ID，正文前有 YAML 元数据。

```markdown
---
title: 测试环境切换
description: 切换时间、负责人和回滚约定。
load: on-demand
sourceMessageIds: ["12345", "12348"]
---

切换时间为周五 22:00。部署失败时回滚到上一版本。
```

配置开启后，运行数据保存到 `data/notes/<平台>/<会话 ID 的 UTF-8 十六进制>/<笔记 ID>.md`。Agent 通过 `write_note` 创建或更新按需笔记，重复调用相同 ID 更新同一条。维护者可在文件中把 `load` 改为 `always`，也可以手工维护常驻笔记。新笔记及手工修改在下一轮可见。

## 每群配置

```yaml
chats:
  default:
    notes:
      enabled: false
      alwaysLoad:
        maxContextEstTokens: 2000
      onDemand:
        maxContextEstTokens: 8000
```

两个数字均为每次模型请求的估算上限，沿用现有 Driver 的文本估算方式。它们可以在群配置中分别覆盖。常驻预算包含显示给模型的标题及正文，按需预算包含索引和本轮读取的笔记。首次请求只扣除已注入的常驻内容和索引。读取正文后，Driver 按实际页长计算上下文占用，必要时裁剪较早的历史，并保留最近一条上下文。常驻内容按笔记 ID 排序加载，超出预算的条目整条略过，仍可按需读取。

## 模型工具与运行边界

- `write_note` 接收 ID、标题、简介、正文及可选的来源消息 ID。单独写入成功即可静默结束本轮。写入失败时，下一步保留笔记 ID 和工具错误，供模型修正参数。
- `load_note` 通过 ID 读取当前群的笔记。返回正文及可能存在的续读位置，结果计入本轮的按需预算。模型收到这一页并成功返回后，Driver 将正文版本和续读位置保存到同目录的 `<id>.cursor`。跨轮次或重启后省略 `offset` 即可续读；显式传 `0`、正文发生变化或已经读完时从头开始。
- 主轮次和压缩请求按相同顺序组装工具定义。压缩阶段由现有的 `local-none` 策略阻止工具执行。
- Driver 为主 Agent 组装笔记索引、常驻正文和工具，渲染内容计入模型上下文。笔记工具的输入、结果成对从持久化轮次中移除，防止笔记正文通过对话回放重复计入。聊天事件、压缩摘要和笔记各自保存。
- 笔记正文是参考资料，系统提示词负责告知模型如何判断何时写入，以及如何使用笔记。模型调用笔记工具时只提供笔记 ID，平台和会话由 Driver 绑定。

## 验收

- 笔记关闭时，主 Agent 的工具和上下文保持原有行为。
- 模拟模型只调用 `write_note`，验证笔记保存成功且没有群消息或额外模型请求。
- 重启后读取同一群的笔记，验证另一群读取不到同 ID 的内容。
- 在一个请求中验证常驻预算，在一次轮次的连续模型步骤中验证按需预算，并确认回放历史不含笔记工具正文。
